# Research Lineage & Repository Map

Date: 2026-09-19

## Purpose

This document treats the GitHub account as a **longitudinal research corpus** rather than as a flat list of repositories.

The working model is:

**Historical record → research domain → artifact → architectural layer → evidence status → canonical owner**

A repository can preserve important research history without being part of the current production/core architecture.

## Historical horizon

The broader research record is described as approximately decade-scale based on the researcher's stated history. The GitHub evidence available in the current account does **not by itself establish a continuous ten-year GitHub record**. Earlier periods therefore remain:

**HISTORICAL / SOURCE RECORD RECONSTRUCTION REQUIRED**

No unverified earlier date is presented as a proven publication or implementation date.

## Compilation rule

Historical repositories are **compiled, not erased**.

For each source repository:

**PRESERVE → CLASSIFY → LINK → NORMALIZE → EXTRACT RESEARCH ASSET → ASSIGN STATUS → ASSIGN CANONICAL OWNER**

Only after those steps should material be migrated into WANGA-LAB or another current canonical repository.

## Evidence rule

A repository's age, commit count, or file count is not proof of a research claim.

The public record distinguishes:

**HISTORICAL → SPECIFIED → BUILT → PROTOTYPED → TESTED → VERIFIED → PUBLISHED**
